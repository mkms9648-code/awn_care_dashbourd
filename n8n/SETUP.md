# مساعد المبيعات — إعداد n8n (نص + قراءة صور)

المساعد بيشتغل عن طريق **n8n**. اللوحة بتبعت السؤال (ومعاه صورة اختيارية) لـ webhook،
والـ webhook بيقرا "المعرفة" من Supabase، يسأل **Gemini**، ويرجّع الرد.

## عقد الاتصال (Contract)

**الطلب** (POST JSON من اللوحة):
```json
{
  "product": "awncare | fathi",
  "message": "سؤال الموظف",
  "session_id": "…",
  "history": [ {"role":"user|assistant","content":"…"} ],
  "image": "data:image/png;base64,....",   // اختياري (سكرين شوت)
  "image_mime": "image/png"                 // اختياري
}
```
**الرد** المتوقع: `{ "reply": "رد المساعد" }` (اللوحة بتقبل كمان `output`/`text`/`answer`).

## الخطوات (القالب الجديد بيقرا الصور)

1. **استورد** `sales-assistant.json` (Import from File). الفلو:
   `Webhook → Get KB → Build Gemini Request (Code) → Gemini (HTTP) → Respond`.
2. **مفتاح Gemini**: افتح نود **Gemini** وغيّر `YOUR_GEMINI_API_KEY` في آخر الـ URL
   بمفتاح Google AI Studio بتاعك (نفس المفتاح اللي ورا كريدنشال Gemini في فلوزك).
   تقدر تغيّر الموديل كمان (مثلاً `gemini-2.0-flash` أو `gemini-1.5-pro`).
3. **Get KB**: بيقرا من دالة `sales_kb_get` على مشروع عون كير (المفتاح anon متحطوط).
   لازم تكون شغّلت `sql/026_sales_assistant.sql` الأول.
4. **فعّل** الـ workflow، وخُد الـ **Production URL** (المفروض نفسه:
   `.../webhook/sales-assistant`) — وهو أصلاً متحط في `config.js`.
5. من اللوحة → مساعد المبيعات → **تعديل المعرفة** → املأ الشخصية + الأسعار/الباقات/
   الدفع/اللينكات، واحفظ.

## قراءة السكرين شوت
- الموظف بيضغط زرار الصورة 📷 في الشات، يختار سكرين شوت (مثلاً محادثة واتساب مع عميل)،
  ويكتب "رد عليه إزاي؟" ويبعت. الصورة بتتبعت base64 جوه نفس الطلب.
- نود **Build Gemini Request** بيحط الصورة كـ `inline_data` مع آخر رسالة، وGemini
  بيقراها. الحد الأقصى للصورة من اللوحة 5 ميجا.

## زرار النسخ
تحت كل رد من الـ AI فيه زرار 📋 بينسخ نص الرد — شغّال تلقائيًا، مش محتاج أي إعداد.

## أمان وملاحظات
- المفتاح في الـ URL بيفضل داخل n8n بس (مش في المتصفح) — آمن.
- ممكن تحمي الـ webhook بـ Header Auth في n8n لو حبيت تمنع أي استدعاء خارجي.
- `sales_kb_get` بترجّع معلومات المبيعات بس (مش سرية).

## اختبار الذكاء الاصطناعي (AI QA Tester)

صفحة **اختبار الذكاء الاصطناعي** في عون كير بتشغّل AI (Gemini في n8n) بيلعب دور
"دكتور مختبِر" — بيكلم بوت حقيقي (طوارئ/راوند/عيادة) عن طريق نفس الـ webhook اللي
التطبيق الحقيقي بيستخدمه، والمطوّر يتفرج بس على المحادثة وهي بتحصل.

### عقد الاتصال (Contract)

**الطلب** (POST JSON من اللوحة):
```json
{
  "system_prompt": "شخصية/تعليمات الدكتور المختبِر — من bot_test_personas",
  "message": "آخر رد من البوت الحقيقي (فاضي في أول رسالة)",
  "history": [ {"role":"user|assistant","content":"…"} ]
}
```
**الرد** المتوقع: `{ "reply": "رسالة الدكتور المختبِر التالية" }` — لو النص فيه
`END_TEST` كده الاختبار خلص (اللوحة بتوقف الحلقة وما بتبعتش الرسالة دي للبوت
الحقيقي أصلاً). لو الرد بيبدأ بسطر `[FLAG: وصف المشكلة]` — ده التستر بيبلّغ عن
حاجة حسّها غلط في رد البوت اللي فات؛ اللوحة بتشيل السطر ده وتعرضه كملاحظة حمراء
منفصلة في المحادثة (وفي التقرير المُصدَّر)، وبتكمّل بالرسالة العادية اللي بعده.

### الخطوات

1. **استورد** `ai-tester.json` (Import from File). الفلو:
   `Webhook → Build Gemini Request (Code) → Gemini (HTTP) → Respond` — أبسط من
   مساعد المبيعات لأن مفيش قراءة من Supabase؛ الشخصية بتتبعت جاهزة مع كل نداء.
2. **مفتاح Gemini**: افتح نود **Gemini** وغيّر `YOUR_GEMINI_API_KEY` في آخر الـ
   URL بنفس المفتاح اللي حطيته في مساعد المبيعات (أو مفتاح تاني لو حابب).
3. **فعّل** الـ workflow، وخُد الـ **Production URL** (المفروض
   `.../webhook/ai-tester`) — وحطّه في `config.js` تحت
   `PRODUCTS.awncare.AI_TESTER_ENDPOINT`.
4. لازم تكون شغّلت **`sql/043_ai_qa_tester.sql`** الأول على مشروع عون كير —
   مش عشان n8n يقرا منه (n8n مبيلمسش Supabase في الفلو ده خالص)، بس عشان
   اللوحة يبقى عندها مكان تحفظ فيه شخصيات الاختبار وهوية الدكتور التجريبي.
5. من اللوحة → اختبار الذكاء الاصطناعي → اختار بوت → اربط "دكتور تجريبي" (جوّه
   مساحة عمل حقيقية عندها البوت ده مفعّل) → عدّل نص الشخصية لو حبيت → ابدأ.

### لو عندك نسخة مستوردة قبل كده — استوردها تاني
نود **Build Gemini Request** اتحدّث (بروتوكول [FLAG]، وأسلوب اختبار أشد وأكثر
بشرية، ودرجة حرارة أعلى للتنويع). لو كنت مستورد `ai-tester.json` قبل كده، لازم
تمسح الـ workflow القديم وتستورد النسخة الجديدة تاني (أو تفتح نود Build Gemini
Request وتلصق الكود الجديد يدويًا) عشان تاخد التحديث — الاستيراد مش بيحصل
تلقائي.

### ميزات الصفحة (بدون أي تعديل إضافي في n8n)
- **علامة حمراء (🚩)**: التستر بيبلّغ لحظيًا لما يحس إن رد البوت فيه مشكلة —
  اتجاهل معلومة، رد غير منطقي، ناقض نفسه، أو تجاهل تعليمات. بتتحسب في عدّاد
  أحمر أعلى الصفحة.
- **تصدير تقرير نصي**: زرار "تصدير تقرير" بيحمّل ملف `.txt` فيه المحادثة كاملة
  + كل الملاحظات الحمراء مجمّعة في قسم منفصل.
- **متابعة مترابطة بين البوتات**: قبل كل اختبار، اللوحة بتقرا فعليًا مين
  المرضى المسجلين حاليًا تحت الدكتور التجريبي (عن طريق `app_encounter_list` —
  نفس دالة البورد في التطبيق الحقيقي) وتحطهم في تعليمات التستر، عشان الراوند
  مثلاً يتابع نفس مرضى الطوارئ اللي اتسجّلوا فعلاً، ومايخترعش حد مش موجود.

### ملاحظة أمان مهمة
الدكتور التجريبي ده حقيقي وبيبعت رسايل حقيقية للبوت الحقيقي — يعني بيعمل
مرضى/حالات فعليًا في قاعدة البيانات (زي أي دكتور حقيقي). خليه دايمًا هوية واضح
إنها تجريبية (زي "AI QA Tester — طوارئ") عشان محدش يتلخبط بيها لاحقًا، ومتربطش
نفس الدكتور بأكتر من بوت لو مهتم إنك تمسح ذاكرته قبل كل اختبار — المسح بيمسح
ذاكرة كل البوتات اللي عنده مع بعض، مش بوت واحد بس.
